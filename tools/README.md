# Tools (Dev-Only Utilities)

These scripts are NOT runtime code — they assist humans authoring tax form mappings.

## extract-acroform-fields.ts

Extracts AcroForm widget metadata from a PDF and emits YAML compatible with the W4 form mapping schema (as a starting skeleton — you must add `sourcePath` + `citation` per field manually).

### Usage

```bash
pnpm extract:acroform --pdf path/to/source.pdf
pnpm extract:acroform --pdf path/to/source.pdf --out app/src/forms/DE/2024/mantelbogen.skeleton.yml
```

### Workflow

1. Download official source PDF (e.g. BMF Mantelbogen ESt 1A 2024).
2. Run the extractor: `pnpm extract:acroform --pdf bmf-mantelbogen-2024.pdf`
3. Pipe to file or use `--out` to save.
4. Hand-review every field:
   - Drop fields you don't need (most forms have 100+ widgets, MVP uses 8-20).
   - Add `sourcePath` linking to the user data bundle (e.g. `calculation.de.income.gross`).
   - Add `citation` to the BMF reference URL or doc anchor.
   - Add the wrapping `country, year, form, formTitle, sourceUrl, sourceVersion` keys.
5. Validate by running tests against the new mapping (see W4 T1.3).

### Why not auto-generate sourcePath?

Tax law changes annually. Auto-mapping risks silent wrong-box errors (legal liability). Every field must be a human decision with a citable source. See `app/src/prompts/f4-harness/` for the F4 anti-hallucination playbook.

### Output Example

```yaml
# Auto-extracted AcroForm fields from: mantelbogen-2024.pdf
# Generated by app/tools/extract-acroform-fields.ts
# Hand-edit to add: country, year, form, sourceUrl, sourceVersion, sourcePath, citation
# DO NOT commit this raw output as a mapping — review every field, drop unused ones, add citations.

# Found 3 field widget(s) across 1 page(s).

extracted_fields:
  - name: "TaxpayerName"
    type: PDFTextField
    page: 0
    rect: [50, 700, 200, 20]

  - name: "GrossIncome"
    type: PDFTextField
    page: 0
    rect: [50, 650, 100, 20]

  - name: "JointFiling"
    type: PDFCheckBox
    page: 0
    rect: [50, 600, 15, 15]
```
